# 商务标多格式适配（一期）实施计划

> 面向 agentic worker：按任务逐个实现，每任务遵循 TDD 循环（写失败测试→跑→实现→绿→commit）。
> 需求文档：《商务标多格式适配-需求分析》V1.0（`D:\00工作+学习\宏信天德\投标助手\需求分析\`）。

**Goal:** 上传任意招标文件（docx/doc/文本型PDF）后，裁切其"投标文件格式"章节为商务标底稿，用户逐表确认表格绑定后按绑定填充人员/业绩/证书扫描件，导出附带填充报告与防篡改校验；无底稿时回退旧模板导出。
**Architecture:** 底稿必须从招标文件确定性裁切（XML 保真，固定格式页不得修改）；废弃固定标题定位表格，改为表头关键词签名分类 + 用户确认的 bindings JSON 绑定驱动填充；LLM 不进数据路径。
**Tech Stack:** FastAPI + SQLite + python-docx + fitz + pdf2docx + pywin32(Windows)；Vue3 + Element Plus。
**Spec:** docs/plans + 需求分析 docx。

## 全局约束
- 后端运行目录 `backend/`；测试 `cd backend && python -m pytest tests/ -x -q`。业务逻辑在 `app/core/`（纯函数）与 `app/services/`（编排/DB），路由只做校验+调用。
- 英文标识符、中文 docstring/错误消息、dict 传递数据。DB 访问走 `app/db.py:Database`，JSON 列 `json.dumps(ensure_ascii=False)` 存 / `json.loads` 读。
- 错误码：404 "项目不存在"；400 输入错误；422 业务校验失败；503 配置缺失。动作类成功响应 `{"ok": True, ...}`。
- 新表进 `Database.init_schema()` 用 `CREATE TABLE IF NOT EXISTS`（幂等）。
- 新增 config 目录常量必须同步在 `backend/tests/conftest.py` 里 monkeypatch。
- docx fixture 按 `test_bid_template.py:_build_template` 程序化构造；真实招标文件用 `pytest.mark.skipif` 门控。
- 前端 `frontend/src/api/index.js` 每个函数 `api.xxx(...).then(r => r.data)`；构建 `cd frontend && npm run build`。UI 文案中文。
- 每任务结束 git commit（中文短句）。
