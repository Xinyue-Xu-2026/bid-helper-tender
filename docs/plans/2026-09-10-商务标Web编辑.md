# 商务标 Web 内编辑（方案 A：结构保真内容编辑器）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (or executing-plans) to implement task-by-task. Steps use `- [ ]` checkbox syntax.

**Goal:** 在 Web 内原位编辑商务标底稿的文字内容（段落 + 表格），并支持简历表「复制本表 → 每人一份」；同时修复简历表自动克隆分类 bug。

**Architecture:** 后端用 python-docx 把底稿 body 按序读成「块序列」（段落 + 表格逻辑网格），前端渲染为可编辑界面；用户只改文字，后端**原位改写 run 文本**（不重建文档），合并单元格/行列/行高/字体全保留 = 零排版丢失。编辑结果存为独立「编辑版底稿」（`bid_templates.edited_path`），导出以编辑版为底稿、防篡改校验以编辑版为基准。简历表复制复用已实现的 `_clone_table_after`（XML 级 deepcopy）。

**Tech Stack:** FastAPI / python-docx + lxml（后端）；Vue 3 + Vite（前端）。

**Spec:** 需求为对话确认（方案 A + 一起修自动克隆）；诊断结论见本计划「附录 A」。

## Global Constraints
- 后端 `python -m pytest` 全绿（当前基线 342 passed）；前端 `npm run build` 绿。
- **只改文字，不改结构**：段落/表格正文编辑一律原位写 run 文本，绝不重建 docx；合并单元格/行列/行高/样式必须逐字节保留（除"复制表"这一项显式结构操作）。
- 编辑版底稿与原始底稿分离；导出/校验以编辑版为准；无编辑版时行为不变。
- 迁移幂等；英文标识符、中文文案；每任务独立 commit，message 前缀 `商务标：`。
- 真实数据只读诊断，测试程序化构造。

## Track A：Web 内容编辑器

### Task A1 — 底稿块序列读写核心（`doc_blocks.py`）
**Files:** Create `backend/app/core/doc_blocks.py`；Test `backend/tests/test_doc_blocks.py`。

**Interfaces (Produces):**
- `read_blocks(docx_path) -> {"blocks": [...], "n_tables": int}`：按 body 顺序产出块；paragraph 块 `{"kind":"paragraph","index":i,"text":str}`；table 块 `{"kind":"table","index":j,"cells":[[{"text","colspan","rowspan","origin"}]]}`（用 gridSpan/vMerge 展开逻辑网格，origin 标记该格是否为首格）。
- `apply_edits(docx_path, out_path, paragraphs: dict[int,str], tables: dict[int, list[list[str]]], clones: list[dict]) -> dict`：复制 docx_path→out_path；对段落按 index 原位改文本（复用 `_rewrite_paragraph_text`，保留首 run 格式）；对表格按矩阵写文本（复用 `_set_cell_text`，自动跳过非文本段落）；`clones: [{"table_index":idx,"count":n}]` 调 `_clone_table_after` 复制 n 份（表间空段分隔）。返回变更摘要。
- 段落文本读取用 `_para_text`（仅 run 文本，图片/文本框段落文本为空但保留）。

- [ ] **Step 2 跑测试确认失败** → `pytest tests/test_doc_blocks.py -q`

- [ ] **Step 4 跑测试通过 + 全量** → `pytest -q`

### Task A2 — 编辑版底稿存储与导出接入

## Track B：修复简历表自动克隆分类

### Task B1 — 分类器修复
**Files:** `backend/app/core/bid_table_classifier.py`；Test `backend/tests/test_bid_classifier.py`。

**根因**（附录 A）：person_roster 规则先于简历表规则 + ncols 6~9 死区 + 标记"执业资格证书名称"不匹配"执业资格证书（或上岗证书）名称"。

**修改：**
1. 在 person_roster/perf_list 判定**之前**新增「简历样表优先识别」：全表任意单元格命中简历标记（放宽为 `执业资格`、`执业资格证书`、`拟在本项目任职`、`主要工作经历` 任一，子串匹配）且第 0 列逐行命中 `RESUME_LABELS` ≥3 → 直接 `resume_each`（`mode="per_person"`、columns 用 `_match_resume` 产出）。
2. 移除 ncols 死区：简历表识别不再要求 `2~5 或 ≥10`，改为 `ncols >= 2`（键值样表与大网格均可）。
3. 标记匹配用子串（`执业资格证书名称` 命中 `执业资格证书（或上岗证书）名称` 中的 `执业资格证书`）。

- [ ] **Step 2 跑测试失败 → 实现 → 通过**；全量 `pytest -q`
